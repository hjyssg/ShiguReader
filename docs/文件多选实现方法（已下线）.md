# 文件多选实现方法（已下线）

> 状态：**已下线（当前版本仅保留单选）**

## 背景

历史版本在文件浏览器里实现过多选能力（主要是 Explorer 文件列表）。

但在实际使用中，多选状态维护与批量操作会增加前端交互复杂度，带来明显“迟钝感”（点击、右键、快捷键链路更重，状态切换更多），因此当前版本已移除多选，回退为单选优先。

## 历史多选实现思路（回顾）

原实现主要由以下几部分组成：

1. `useFileSelection` 维护 `selectedPaths: Set<string>`
   - 单击：替换选择
   - Ctrl/Cmd+点击：切换选择
   - Shift+点击：范围选择
   - 提供 `selectAll`、`clearSelection` 等能力

2. `useFileExplorerKeyboard`
   - 监听 `Ctrl/Cmd + A` 做全选
   - `Delete / F2 / Enter / Escape` 依据选中数量触发行为

3. `FileContextMenu`
   - 根据 `selectedCount` 动态文案（如 `Move N items` / `Delete N items`）
   - 提供 `Select All` 入口

4. `FileViewContainer`
   - 作为状态聚合层，把“选择状态 + 快捷键 + 右键菜单 + 对话框”串起来
   - 承担批量删除、批量移动等批处理入口

## 当前版本调整

当前版本已做如下收敛：

- 移除 Ctrl/Cmd、Shift 的多选行为（点击仅单选）
- 移除键盘 `Ctrl/Cmd + A` 全选
- 移除右键菜单 `Select All`
- 移除选择工具栏与批量文案分支
- 相关环境开关（`VITE_DISABLE_GRID_MULTI_SELECT`）已清理

## 后续若要重启多选（建议）

如果未来要重新引入多选，建议以“性能与感知优先”方式重做：

1. 先定义可接受的交互延迟指标（点击反馈、菜单弹出、批量操作确认）
2. 分阶段上线（先仅 table，再 grid；先 2~3 个批量操作）
3. 将多选逻辑封装在独立层并加埋点，便于灰度与回滚
4. 默认关闭，按场景/用户配置逐步开放
