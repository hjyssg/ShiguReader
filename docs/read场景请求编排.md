# Read 场景请求编排

## 1. 目标与范围

本文定义 Read 场景在“打开内容”时的业务编排规则，目标是：

- 用统一入口支持 archive / audio / image / folder 四类来源。
- 明确每类来源的首个请求行为。
- 控制请求数量，避免同一次打开触发多路重复请求。

---

## 2. 场景对象

- **打开目标**：用户准备进入阅读或播放的路径对象。
- **来源类型**：`archive` / `audio` / `image` / `folder`。
- **父目录上下文**：用于构建同级导航与返回路径。

---

## 3. 打开时业务流程

1. 系统识别打开目标类型。
2. 根据类型选择唯一主请求路径：
   - `archive`：先执行一次解压请求。
   - `audio` 或 `image`：请求其父目录列表。
   - `folder`：请求当前目录列表。
3. 首次编排只允许一条主查询链路，避免重复拉取。
4. 响应到达后构建阅读上下文（序列、导航、当前位置）。

---

## 4. 编排规则

1. **单次打开，单主请求**
   - 同一打开动作只应存在一个主查询函数入口。

2. **archive 优先解压**
   - 解压是 archive 打开场景的前置条件。

3. **image/audio 依赖父目录**
   - 这两类来源以父目录列表作为序列基础。

4. **folder 以当前目录为准**
   - 不额外回溯父目录作为主数据源。

5. **编排机制语言无关**
   - 可由任意运行时机制实现（事件、状态机、effect、协程等），
     但业务语义必须一致。

---

## 5. 异常与降级

- archive 解压失败：返回可理解错误并允许重试。
- 目录列表失败：维持当前界面状态，不进入错误数据上下文。
- 类型识别失败：按不可处理目标返回统一错误。

---

## 6. 验收口径

1. 四类来源都能按规则进入正确请求路径。
2. 单次打开不会触发重复主查询。
3. archive 打开必经解压，成功后可进入阅读上下文。
4. image/audio/folder 的序列来源符合规则定义。
