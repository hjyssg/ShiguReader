# 用 Explorer 浏览解压内容

## 1. 目标与范围

本方案定义“压缩文件浏览”能力的统一入口：用户点击压缩文件后，不再进入独立页面，而是进入 Explorer 场景完成解压后的内容浏览。

目标是让“普通目录”和“压缩文件”在用户认知上尽量一致。

---

## 2. 业务流程

1. 用户在文件列表中点击压缩文件。
2. 系统进入 Explorer，并携带“待解压来源”信息。
3. Explorer 检测到该信息后触发解压流程。
4. 解压成功后，页面路径切换为解压缓存目录。
5. 用户继续以普通目录方式浏览、进入阅读、返回。

---

## 3. 业务规则

1. **入口统一**
   - 压缩文件与目录都从 Explorer 进入，不新增平行浏览器入口。

2. **解压触发时机明确**
   - 仅当 Explorer 检测到“待解压来源”时触发解压。

3. **解压结果可复用**
   - 已解压内容应优先命中缓存，避免重复等待。

4. **状态参数仅用于过渡**
   - “待解压来源”属于流程参数，完成跳转后可清除，不应长期保留。

5. **返回链路一致**
   - 从阅读页、音视频页返回时，应回到 Explorer 场景，不回退到已废弃的旧入口。

---

## 4. 用户体验要求

- 解压期间提供明确加载态。
- 命中缓存时应尽量无感切换。
- 用户无需理解“解压页”和“浏览页”的区别。

---

## 5. 影响与兼容

- 旧的独立压缩文件页面链接不再作为主流程。
- 书签或历史链接如仍指向旧入口，可视为兼容降级范围。

---

## 6. 验收口径

1. 点击压缩文件后可稳定进入 Explorer 并完成解压浏览。
2. 阅读/音视频场景返回时路径正确指向 Explorer。
3. 同一压缩文件二次进入时可复用缓存，响应明显更快。
4. 用户全程只感知“在 Explorer 浏览内容”。
